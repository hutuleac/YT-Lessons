Auto mode and the permission ladder

Permission modes are a spectrum of how much the agent asks before acting, and auto mode — now the default — resolves each action against your written rules first, falling through to a separate classifier model only when the rules are silent.

Software Engineer Meets AI · Claude Code Auto Mode: This Is the New Default · 4:43 ↗

Auto mode and the permission ladder14 / 47

Auto mode and the permission ladder

  1. A permission mode sets how much the agent asks before it acts.
  2. Auto mode is the new default: it does almost everything, blocking dangerous actions.
  3. Every action hits your rules first — exact matches never reach the classifier.
  4. Only unmatched actions go to a classifier that asks two questions.
  5. The classifier's decisions are practically invisible without OpenTelemetry.

What to do

  • Write rules for the actions you already have an opinion on — they resolve before any model runs.
  • Use hard deny and ask rules for real limits; environment and soft deny are only guidance.
  • Describe your infrastructure in the environment field so the classifier judges in context.
  • Avoid bypass-permissions; auto plus rules gives you the speed without losing the checks.
  • Assume you cannot audit classifier decisions after the fact, and put the important ones in rules.

Auto mode's empirical safety record

  1. Users approve 97% of permission prompts — reviewed reflexively, not read.
  2. Blind study: humans caught 13.6% of a swapped-in dangerous command; auto mode caught 89%.
  3. Human catch rate fell over a session, from 17% to 5%; auto mode's stayed flat.
  4. In flagged production sessions, manual approval had over twice the rate of unintended harm.
  5. Adversarial red-teaming with Apollo Research cut the classifier's miss rate from 12% to 7%.

What to do

  • Treat 97% approval rates on your own prompts as a warning sign, not reassurance — that's exactly the habituation the data shows.

Your effort level is too high

  2. Exploration barely benefits from effort — it just costs more.

Read the cost-quality curve

  1. Plot quality against average cost per task, not quality alone.
  2. Each model traces a curve as its effort level rises.

An agent's output quality is bounded by the codebase it works in, and unlike a human it has no memory to route around a bad one — so software fundamentals matter more now, not less.

The code is the agent's environment

  1. The codebase is the environment the agent operates in.
  2. A garbage codebase produces garbage output.
  3. Humans build a feel for a bad codebase. Agents cannot — no memory.
  4. So the same mistakes repeat, on dumb models and smart ones alike.

  • Stop reaching for a smarter model when the real obstacle is the environment.

There is no such thing as greenfield

The only real difference between a greenfield and a brownfield codebase is that one has settled conventions and the other hasn't yet — and with an agent filling the repo, that distinction survives about a week.

There is no such thing as greenfield

  1. Everything is built for the real world, with real constraints.
  2. Brownfield means the conventions already exist, often only in the code.
  3. Greenfield just means you pick them — once.
  4. A repo goes from fresh to legacy faster than ever now.
