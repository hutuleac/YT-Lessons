Prompt caching4 / 24

Prompt caching

  1. Each message resends your full chat history.
  2. The cache stores that history for fast, cheap reads.
  3. Writing to the cache costs more than reading from it.
  4. The cache ends after 1 hour with no new messages.
  5. Switching models or running /compact ends the cache early.

What to do

  • Send your next message within the hour to keep the cache warm.
  • Avoid changing model, effort, or MCPs mid-task if the cache matters to you.
  • Need a fast, cheap answer mid-session? Say "give me a quick answer" instead of switching model — it skips deep reasoning without resetting the cache.
  • Use 5-minute caching on the API for quick, one-off calls; use 1-hour for longer work.
  • Plan your break before it happens: /clear, /compact, or hand off — not after.

Clear, compact, or handoff

When the cache is gone, pick one of three moves: keep nothing and let the project carry the context, summarise into the next chat, or write the summary to a file on disk.

Clear, compact, or handoff

  1. /clear wipes the chat. The project files carry the context forward.
  2. /compact summarises the chat, then starts a new one with that summary.
  3. A handoff writes the summary to a file on disk instead.
  4. Compact and handoff do the same summary step. Only the storage differs.
  5. Do this before you hit the auto-compact limit, not after.

Rewind, don't patch forward

A broken output is cheaper to undo than to fix — rewind to before it happened and regenerate, instead of asking the agent to correct its own mistake.

Rewind, don't patch forward

  1. A broken output: rewind to before it, don't ask for a correction.
  2. Rewind restores the session's own context — nothing is lost by going back.
  3. It does not undo bash. A deleted file needs git, not rewind.
  4. Clearing context is also recoverable this way, contrary to how it feels.

Advisor mode

  1. A strong model plans the task.
  2. A cheap model executes the plan, turn by turn.
  3. The executor calls the planner back only when it gets stuck.
  4. Planner and executor each keep their own separate cache.
  5. The executor can be a different model family, not just a cheaper Claude.

Timing beats trimming

A "be brief" rule only trims output tokens, a small line item. Prompt caching sets the price of your whole input history, and it swings 20x on timing alone: inside the hour, or outside it. Keep the cache warm while you work. Have a plan for when it is gone. Send cheap steps to a cheap model.
