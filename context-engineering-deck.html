The dumb zone

  1. A 1M-token window is not 1M tokens of usable work.
  2. Add a token and the model tracks every relationship it has to every other token.
  3. Performance sinks gradually — there is no cliff, so nothing warns you.
  4. Rule of thumb: the dumb zone starts around 150k tokens.

What to do

  • Break work into small chunks and run each in a fresh context window — fewer tokens spent, better results.
  • Treat arrival in the dumb zone as a signal to clear, compact, or hand off to a new session.
  • Not every task needs the smart zone. Cheap, mechanical work can run in the dumb zone on purpose.
  • Redesign workflows so tasks don't need that much context in the first place.

Tool definitions are context

  1. The more tools you give an LLM, the worse it performs.
  2. A tool is not code to the model — it is a title, a description and a JSON schema.
  3. All of it sits in the system prompt, above everything else you sent.
  4. Six to eight is fine. Dozens fills the window before you have said anything.

Skill hell

What to do

  • Run one framework properly instead of three partially — overlap is what floods the window.
  • Read a skill before installing it. Loading it to see if it works is the whole failure mode.
  • Judge a skill by whether it makes your process repeatable, not by how autonomous it is.
  • Sequence stages so each loads only what it needs, then delegate the stage and step away.

Factuality vs faithfulness

One question splits every hallucination into two kinds with two different fixes: was the information in the context window at all?

Factuality vs faithfulness

  1. Hallucinations are probably inherent to LLMs. Diagnose, don't hope.
  2. Ask one question: was the information in context?
  3. It wasn't → factuality. The model was recalling. Load the information.
  4. It was → faithfulness. The model drifted. Get out of the dumb zone.

What to do

  • Before fixing anything, check whether the information was ever in the context window.
  • Factuality: load the source. Never trust an unsourced answer.
  • Faithfulness: clear, compact, or hand off — don't re-prompt into the same long window.
  • Read repeated faithfulness failures as a dumb-zone signal, not a model-quality signal.

In one move23 / 23

The whole lesson in one move

There is one resource, it degrades as it fills, and almost every fix is the same fix: put less in the window. Fewer tools, smaller tasks, fresh sessions. The threshold moves as models improve — the mechanism doesn't.
